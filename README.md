# BTC 5분봉 가상 매매 봇 (원칙 v1.4.1 + 쉽알남 자금 관리)

송민제님의 **비트코인 5분봉 모의투자 원칙 v1.4.1**을 GitHub Actions에서 5분마다 자동으로 돌리는 **가상 매매 봇**입니다.

> ⚠️ **실제 돈은 전혀 쓰지 않습니다.**
> 거래소에는 누구나 볼 수 있는 **공개 시세(5분봉 캔들)만 조회**하고, 주문 API·API 키는 아예 쓰지 않습니다.
> 매매는 봇이 자기 장부(`ledger/`)에 "샀다고 치고" 기록하는 것뿐입니다.

## 계좌 보는 법

- **`ledger/ACCOUNT.md`** — 사람이 읽는 계좌 요약. GitHub 저장소에서 이 파일을 열면 됩니다(휴대폰 브라우저도 OK).
  - 맨 위: **포지션: 있음/없음**
  - 거래 시드·지금 1R 금액·출금 누적·잔고+출금 합계·원금 회수 상태
  - 누적손익·승률·최대낙폭(MDD)·오늘 목표/손실 한도·첫 매매 결과·다음 매매 크기·오늘 신규 금지 여부
  - 현재 포지션 표(방향·셋업·등급·진입가·손절·T1·수량·레버리지·미실현손익)
  - 최근 거래 20건, 주간 손익, 셋업별 성적
- `ledger/trades.csv` — 전체 거래 목록(엑셀로 열 수 있음)
- `ledger/status.json` — 기계가 읽는 현재 상태
- `state/bot.log` — 실행 기록(경고 포함)

## 휴대폰 알림 설정 (ntfy, 무료·가입 없음)

1. 휴대폰에 **ntfy** 앱 설치 (안드로이드: Play 스토어 / 아이폰: App Store에서 "ntfy")
2. 앱에서 **+ (Subscribe to topic)** → 토픽 이름 입력. 예: `minje-btc-7f3k9q2x`
   - 토픽 이름을 아는 사람은 누구나 알림을 볼 수 있으니 **남이 못 맞힐 긴 이름**으로 정하세요.
3. GitHub 저장소 **Settings → Secrets and variables → Actions → New repository secret**
   - Name: `NTFY_TOPIC` / Secret: 2번에서 정한 토픽 이름
4. 끝. 다음 실행부터 새 이벤트가 생기면 알림이 옵니다. 예:
   - `🟢 롱 진입 [구간A] 89,120,000 / 손절 88,760,000 / T1 89,600,000 / 0.0069 BTC (0.7배)` (숏은 🔵)
   - `✅ T1 반익절 +1,234원`
   - `🔴 손절 −2,500원`
   - `✅ 청산(거래량 급증) 거래 합계 +3,850원 / 이번 청산 +2,186원`
   - `⛔ 오늘 신규 금지(2연속 손절)`
   - `🎯 하루 목표 달성(+20,500원) — 이후엔 목표가 남는 크기로만`
   - `💸 출금 12,000원(지난주 수익의 30%) — 출금 누적 12,000원`

`NTFY_TOPIC`이 없으면 알림 없이 장부만 기록합니다. 같은 이벤트는 `state/notified.json`으로 관리해 두 번 보내지 않습니다.
봇이 3시간 넘게 멈췄다가 다시 돌면, 그동안의 이벤트는 하나씩 보내지 않고 "N건 생략" 한 줄로 알려 줍니다.

## 처음 올리는 법

1. 이 폴더를 GitHub 저장소로 올립니다(`config.json`의 `start_time`은 `null` 그대로 두세요).
2. 저장소 **Actions** 탭 → "BTC 가상 매매 봇" → **Run workflow**로 첫 실행.
   - 첫 실행 때 과거 3일치 봉을 받아 지표를 준비하고, `start_time`을 그 시각으로 채웁니다. **가상 매매는 그 이후 봉부터** 시작합니다.
3. 그 뒤로는 5분마다 자동 실행됩니다.

**확인할 것**
- **Actions 사용 시간:** 공개(public) 저장소는 무료·무제한입니다. **비공개(private) 저장소는 무료 한도(월 2,000분)를 넘습니다** — 5분마다 실행하면 실행 1회가 최소 1분으로 계산돼 한 달 약 8,600분입니다. 비공개로 쓰려면 cron을 `*/15`(약 2,900분)나 `*/30`으로 늘리세요(빠진 봉은 다음 실행에서 채우므로 결과는 같고, 알림만 늦어집니다).
- 푸시가 거부되면 Settings → Actions → General → Workflow permissions를 **Read and write**로 바꾸세요.
- GitHub의 예약 실행은 몇 분~수십 분 늦어지기도 합니다. 늦어진 동안의 봉은 다음 실행에서 모두 받아 그대로 계산하므로 장부 결과는 달라지지 않습니다.

## 어떻게 동작하나

실행할 때마다 (`bot.py`):
1. `data/candles_5m.csv`를 읽고 **업비트** 공개 API(KRW-BTC 5분봉)에서 새로 닫힌 봉을 받아 붙입니다. **진행 중인 봉은 저장하지 않습니다.**
   - 업비트가 실패하면 **빗썸**으로 받습니다. 처음 성공한 출처를 `state/source.json`에 저장해 계속 쓰고, 그 출처가 실패할 때만 다른 쪽으로 받으며 경고를 남깁니다. 한 번의 실행에서는 한 출처의 봉만 받습니다(각 봉의 출처는 CSV의 `source` 열).
   - 이미 저장된 봉은 절대 덮어쓰지 않습니다.
2. `start_time` 이전 봉은 지표 준비용으로만 씁니다.
3. 저장된 전체 봉으로 **엔진을 처음부터 다시 돌립니다(결정적 재계산).** 그래서 실행이 늦어지거나 빠져도, 같은 봉이면 언제 돌려도 같은 장부가 나옵니다.
4. 장부(`ledger/`)를 저장하고, 새 이벤트를 알림으로 보냅니다.
5. 워크플로가 `data/ ledger/ state/ config.json` 변경분을 `github-actions[bot]` 이름으로 커밋합니다(`[skip ci]`).

로컬에서 시험: `python bot.py --dry-run` (알림을 보내지 않고 화면에만 출력)

## 규칙 요약 (v1.4.1 신호 + 쉽알남 자금 관리 v1.4.1-mm, `config.json`에서 바꿀 수 있음)

> **계좌 성격:** 이 100만 원은 쉽알남 방식의 **단타 계좌**입니다(단타:스윙:장투 = **2**:3:5 중 2).
> 진입·청산 신호(셋업·손절 위치·T1·반익반본·잔량 청산)는 v1.4.1 그대로이고, **수량·하루 한도·목표·출금만** 쉽알남 방식으로 바꿨습니다.
> 새 기능을 모두 끄면(`dayTargetP 0`, `firstWinHalf false`, `withdrawPct 0`, `riskPct 0.25`, `redPct 0.15`, `dayLossP 2`) 기존 v1.4.1과 거래가 완전히 같습니다.

| 항목 | 값 |
|---|---|
| 방향 | 15분봉 20SMA 5봉 기울기 ±0.02% (직전 확정 15분봉) |
| 셋업 | **구간**(스윙 고저점·FVG·OB 터치 + 확인 캔들 A=장악형/B=양봉·긴 꼬리 + 보조 1개) / **B+** 거래량 단계 돌파(시험) / **C** 가짜 이탈 반전(시험) |
| 보조 조건 | 거래량(감소 후 증가), RSI(롱 40~55 반등 / 숏 45~60 꺾임), 1시간 방향 일치, 15분 FVG 겹침 중 1개 |
| 추격 금지 | 5분 20SMA에서 0.8% 이상 이격 또는 RSI 25 미만·75 초과 |
| 체결 | 봉 마감 신호 → **다음 봉 시가** 진입(+1틱). 손절·T1은 고가/저가로 판정, 한 봉에서 둘 다 닿으면 손절 먼저 |
| 1회 위험(1R) | **거래 시드의 1%** (1시간 방향 반대·B+·C도 쉽알남엔 축소 규칙이 없어 같은 1%, `redPct`로 줄일 수 있음). 손실 뒤에도 같은 비율 — 키워서 복구하지 않음(마틴게일 금지). **1회 위험 5% 초과는 코드로 금지**(`maxRiskCapP`, 설정해도 5%로 잘림) |
| 수량 | 1R ÷ (진입가 − 손절가), 레버리지는 결과값(상한 **10배** 안전장치), 0.0001 BTC 단위 내림 |
| 손절폭 | **0.40% 이상 1.5% 이하**인 자리만 진입 (왕복 비용이 0.25R 이하) |
| 익절 | T1 = 직전 스윙(0.8R 미만이면 진입 안 함, 3R 초과면 1.5R). **T1에서 50% 청산 + 남은 물량 손절을 진입가로** |
| 잔량 청산 | 반대 장악형 / 거래량 20봉 평균 2.5배 / 다음 스윙 도달 / 본절 중 먼저 오는 것 |
| 하루 손실 한도 | 그날(KST) 실현 **−1%** 또는 **2연속 손절**(쉽알남 '하루 2패 종료') → 그날 신규 진입 금지 |
| 하루 목표 | 그날 실현 **+2%** 이상(쉽알남 목표:최대 손실 ≈ 2:1) → 일반 크기 금지. 이후엔 **손절돼도 목표가 남는 크기**(위험 ≤ 오늘 실현 − 목표)만 허용, 그 값이 1R의 20% 미만이면 진입 안 함. (기존 '하루 +2R 이상이면 +1R 보존' 잠금도 그대로 겹쳐 적용) |
| 첫 매매 수익 | 그날 첫 매매가 수익으로 끝나면 그날 다음 매매부터 **수량 절반** |
| 출금 | 매주 **월요일 00:00(KST)** 지난주 실현 수익이 플러스면 그 **30%를 출금**(장투 계좌로 이동)해 거래 시드에서 뺌. 손실 주엔 출금 없음. 출금 누적이 원금 이상이면 '원금 회수 완료' 표시 |
| 하루 기준 금액 | 목표·손실 한도 % 는 그날 첫 봉의 거래 계좌 평가 잔고 기준 |
| 비용 | 수수료 진입·청산 각 **0.05%**, 슬리피지 1틱(1,000원, 시장가·손절만) |
| 초기 자금 | 1,000,000원, 포지션은 한 번에 하나 |

- 파인스크립트에 있던 "진입한 봉에서 바로 청산되면 이후 신규 진입이 영원히 막히는" 버그는 이 엔진에 없습니다(정상 초기화).
- 원칙 문서의 경제 일정·세션 시간·4시간/1시간 핵심 구간·분할 진입·재량 판단은 반영되지 않습니다(파인스크립트와 같은 범위).
- 업비트 현물에는 레버리지·숏이 없지만, 원칙의 모의계좌처럼 "증거금 계좌"를 가정합니다(펀딩비·이자 미반영).

## 파일

| 파일 | 내용 |
|---|---|
| `engine.py` | 신호·체결·장부 계산 엔진 (백테스트 `backtest_v14.py`와 같은 로직, 같은 데이터에서 결과 일치 확인) |

| `.github/workflows/bot.yml` | 5분마다 실행 + 수동 실행, 결과 커밋 |
| `data/candles_5m.csv` | 받은 5분봉 (봇이 생성) |
| `ledger/` | 계좌 장부 (봇이 생성) |
| `state/` | 데이터 출처, 보낸 알림, 실행 기록 (봇이 생성) |

`config.json`의 규칙 값을 바꾸면 `start_time` 이후 전체가 **새 값으로 다시 계산**됩니다(과거 거래도 바뀜). 규칙을 바꿀 때는 `start_time`도 새로 정하거나, 바꾼 날짜를 기록해 두세요.
